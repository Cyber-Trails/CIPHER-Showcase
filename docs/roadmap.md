# Roadmap

[← Back to overview](../README.md)

**These are development goals, not completed capabilities.** Order and scope may change. Status of what exists today: [Capabilities](capabilities.md).

| Priority | Goal | Why |
|---|---|---|
| 1 | **Security validation lab** | Exercise the controls not yet proven in live use (autonomy, delegation) and re-validate blast-radius and prompt-injection defences with simulated agents and hostile web, email and screen content |
| 2 | **Compromise recovery** | Complete containment and recovery (C-13) with a written runbook |
| 3 | **Step-up authentication** | Stronger owner verification for the most sensitive actions |
| 4 | **Real outcome checks** | Close the outcome-verification gap (C-11) for desktop and browser actions |
| 5 | **Reliable desktop and browser control** | Governed, owner-gated control of apps and browser profiles, proven step by step with honest failure reasons |
| 6 | **Responsiveness** | Measure and reduce the time to CIPHER's first spoken word without cutting the owner off |
| 7 | **Resilience domain** | Backup and recovery reasoning, credential resilience, BIA and RTO/RPO reasoning, a resilience dashboard |
| 8 | **Deeper cyber work** | Disk and memory forensics, writing detection rules, VM-based labs, governed security sub-agents |
| 9 | **Ciphlet hardware** | A Pironman-based Raspberry Pi companion device |

Security controls only ever get stricter as capabilities grow, never looser.
